A blockchain can keep data unchanged. It cannot tell you the data was true.

ChainSeal signs every sensor reading inside a secure chip, before anyone can touch it. Scan a QR code and see proof that nothing was forged or edited.

      Temperature, humidity, GPS and shock readings from the node.

    2. Sign
      The ATECC608 chip hashes and signs each reading with a key that never leaves it.
      3. 
      
    3. Seal
      A gateway batches readings into a Merkle root and anchors it on the ledger.

    4. Verify

    Secure the source, not just the storage
    
    
    Most systems trust whoever types the data in. ChainSeal removes that step: the reading is signed by hardware at the moment it is measured, so a forged log or an edited record fails verification.

    Technology
    
    
    
      
    Sensor nodeESP32 + ATECC608 + sensors

    Hardware
    • ESP32 with BLE and Wi-Fi
    • ATECC608 secure element, P-256 keys
    • Temperature, humidity, GPS, shock sensors
    • Li-Po battery and tamper switch
    
      
    Software and chain
    • Firmware in C/C++ (Arduino or ESP-IDF)
    • Gateway and verifier in Flutter and Node.js
    • Hyperledger Fabric chaincode
    • Solidity ERC-721 batch passport
    
      
    Security design
    • Device public keys in an on-chain registry
    • Only hashes on-chain; raw data encrypted off-chain
    • Replay-proof timestamps and nonce
    • Consent and DPDP-aligned storage
    
    
    
  
    

    


    
  
    Feasible with off-the-shelf parts
    
  
    
    
    
      
    Only hashes go on-chain, so fees stay low. The plan moves from a prototype to a campus or cold-chain pilot, then to multi-sector rollout.
    
      
    Challenges and how we handle them
    
      
      
        
    • Physical tampering, fake sensor input: secure element, tamper switch, sensor sanity checks.
      • 
        
    • Weak connectivity, key provisioning at scale: store-and-forward and Merkle batching.
      • 
        
    • Write cost and privacy rules: permissioned ledger, personal data kept off-chain.

    Impact and benefits
    
    
    
      
    Trust at source
    Data is signed by the device before it reaches the chain.
    
      
    Fraud reduction
    Tamper-evident records deter forged logs.
    
      
    Consumer confidence
    Scan a QR to see the verified journey.
    
      
    Provable quality
    Spoilage events are on record for fair disputes.
    
      
    Low cost
    Only hashes on-chain keeps fees minimal.
    
      
    Works offline
    Store-and-forward for weak networks.
    
      
    Open audit
    Any party verifies without trusting one authority.
    
      
    Scalable
    One node design, many sectors.
